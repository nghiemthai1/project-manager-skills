# Project Recovery Advisor: software example

Fictional training scenario. Values and thresholds are examples, not defaults for real projects.

## Dialogue: 16 October

**Mina:** "Can we keep the pilot date by adding people?"

**Advisor:** "Is the limiting factor available engineering capacity, the external interface, or missing acceptance evidence?"

**Mina:** "All three need review; only the interface gap is confirmed so far."

## Recommendation

Do not promise a recovery from additional staffing alone. Ask Omar to validate whether a usable interface subset permits resequencing, assess capacity, and preserve recovery-access acceptance. Compare a scoped deferral, an evidence-backed date change, and the unchanged plan.

CR-001 later approves optional polish deferral and B2 funding. The 28 October acceptance gap shows that those actions did not by themselves make release feasible. D-004 then defers the pilot to 3 November. Recovery success is demonstrated by accepted evidence, not by the existence of a revised plan.

## Repair

**Flawed:** "Add two developers and guarantee the original date."

**Corrected:** "Validate the bottleneck and option assumptions, obtain authority, and check whether the intervention changes delivery evidence."
