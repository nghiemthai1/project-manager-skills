# Sprint Planning: software example

Fictional training scenario. Values and thresholds are examples, not defaults for real projects.

## Relay planning discussion

Priya proposes a goal around demonstrable SAML integration for the pilot. Developers inspect the uncertain audit-interface handoff and Omar's workload before selecting work. The capacity subcase shows Omar eight hours overloaded; team-level spare security hours do not resolve that automatically.

The plan includes acceptance and recovery evidence relevant to the selected work. It records the external interface forecast rather than pretending the receiving team controls it. If the interface is late, the team and Priya discuss useful adjustments consistent with the goal.

The 30 October project target does not become a guarantee that every selected item will finish. Nor does the Sprint ending authorize pilot release without Lena's and Theo's relevant evidence.

## Repair

**Flawed:** "Commit to 20% more points to recover the schedule."

**Corrected:** "Inspect capacity, dependencies, and the goal; select feasible work without weakening Done."
