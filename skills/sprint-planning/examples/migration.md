# Sprint Planning: migration example

Fictional training scenario. Values and thresholds are examples, not defaults for real projects.

## Northstar applicability decision

Northstar uses a hybrid migration approach. If its delivery team is not operating Scrum, Jules should use a rehearsal-cycle plan and avoid labeling ordinary task allocation Sprint Planning. The same practical questions about capacity, acceptance, and dependencies still matter.

For a Scrum team performing migration work, the goal might be a usable, reconciled representative migration increment. Developers forecast work using their own history and current availability; Saira's business acceptance and Rosa's restore expectations remain explicit project constraints.

An end-of-cycle demo with equal record counts does not prove the attachment relationship requirement is met. Failed evidence returns to planning as actual work, not an administrative closure.

## Repair

**Flawed:** "Any two-week migration checklist is Scrum, and the PM commits the team."

**Corrected:** "Use the actual delivery approach and accountabilities. Forecast with the people doing the work and keep acceptance evidence visible."
