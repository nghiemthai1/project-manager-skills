# Northstar: use the actual delivery approach

Fictional training scenario before a migration rehearsal. Northstar uses a hybrid approach. No actual Scrum accountabilities or Sprint cadence are supplied, so Jules creates a rehearsal-cycle planning packet rather than naming an ordinary task list Sprint Planning.

Candidate cycle outcome: a usable representative migrated record set whose relationships can be reconciled and whose recovery procedure can be tested. This is a proposed learning/delivery boundary; the actual population, effort, dates and accepted criteria must be agreed. It does not represent approval to migrate every record or cut over production.

| Candidate work | Inspectable evidence | Constraint / planning state |
|---|---|---|
| Prepare versioned population and mapping | Agreed identifiers, selection rationale and expected relationships | Saira's acceptance basis and Beck/Chen usable handoff needed |
| Execute migration and reconciliation | Counts plus relationship correctness and recorded exceptions | Applicable environment/version and capacity unconfirmed |
| Demonstrate restore | Actual executed recovery behavior against agreed conditions | Rosa's operational requirements, technical executor and review window needed |
| Prepare support guidance | Operators can use instructions for the tested configuration | Must follow actual behavior and known access requirements |

The planning conversation compares available skilled capacity with all required work, including correction, retest and operator evidence. Supplier delivery remains distinct from receiver acceptance. If mapping is unavailable, identify genuinely independent preparation and the point at which the cycle outcome must be revised; do not assume a substitute proves final migration correctness.

If the actual migration team does use Scrum, its Product Owner and Developers can apply the same evidence to a Sprint Goal and team-selected forecast. Names and role acceptance would need confirmation; Jules is not automatically Product Owner or planner of every Developer task. Use the actual Definition of Done and local completion history, not another team's velocity.

Saira's business acceptance, Rosa's operational responsibilities and Noel's project decisions remain separate from the cycle demonstration. Equal counts at a demo do not meet the relationship requirement when attachments point to wrong tickets. Failed results become actual remaining work and may change the next forecast.

**Repair:** “Any two-week migration list is Scrum; PM commits it” misstates both the method and authority. The corrected artifact uses the actual hybrid process and retains clear evidence and planning decisions.
