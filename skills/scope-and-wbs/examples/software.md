# Scope and Work Breakdown: software example

Fictional training scenario. Values and thresholds are examples, not defaults for real projects.

## Relay work packages

1. Access capability: SAML login and recovery access.
2. Observability: agreed audit events and their validation.
3. Verification: security tests, tenant validation, and integration evidence.
4. Service transition: operator guidance, reversal procedure, and ownership acceptance.
5. Project control: coordination, approvals, status, and closure evidence.

SCIM provisioning is excluded. Optional operator dashboard polish is initially inside the approved scope, so its later deferral requires CR-001 rather than a quiet deletion.

A dictionary entry for recovery access specifies an observable recovery demonstration accepted by Lena, with operator usability reviewed by Theo. It does not say merely "implement recovery button."

## Why this works

The breakdown makes security and operational readiness visible as actual work. It also shows why deferring an in-scope item changes the plan even if it is not essential to the pilot's acceptance.
