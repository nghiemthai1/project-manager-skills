# Scope and Work Breakdown: migration example

Fictional training scenario. Values and thresholds are examples, not defaults for real projects.

## Northstar work packages

The migration breaks into population agreement, export/mapping, rehearsal and reconciliation, access validation, restore readiness, support training, cutover, archive access, and closure. Historical analytics redesign remains excluded.

The attachment package covers preserved ticket-to-attachment relationships, not just attachment file transfer. Chen owns technical delivery; Saira accepts the business reconciliation and Rosa accepts the service readiness evidence. These roles appear in the dictionary without treating all three as the same approval.

## Scope decision

If a request adds historical analytics, Jules records the new deliverable and its impact before updating the scope baseline. Calling it "small reporting work" does not place it inside the original charter.

## Repair

**Flawed:** "Transfer database and close project."

**Corrected:** "Deliver agreed records with validated relationships, usable workflows, restore capability, trained support, archive access, and accepted handover."
