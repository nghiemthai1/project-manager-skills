# RACI audit methods

Use audits to find questions that the project must resolve. Do not use them to manufacture a tidy matrix.

## Horizontal row audit

For each bounded deliverable, decision or handoff:

1. Count A and A/R as accountable relationships. The default review convention is one A per row.
2. Count R and A/R as responsible relationships. A row with no R has no explicit performer or coordinator.
3. Identify `?`, disputed state and material assignments that are not confirmed.
4. Review several R assignments for overlapping boundaries. The count alone is not a defect.
5. Review consultation above the declared threshold. Keep a required contributor even when the count is high.
6. Check whether affected downstream roles need an I relationship and a useful communication trigger.

Treat a missing/competing A, missing R or disputed assignment as a governance issue. Treat high C, several R, and incomplete confirmation as review prompts whose meaning depends on the work boundary.

## Vertical role audit

For each role:

- count A/R/C/I/?/— and proposed/confirmed/disputed/unknown states;
- inspect several A assignments against the declared authority and segregation-of-duty needs;
- inspect several R assignments against timing and effort in the capacity plan;
- inspect a high C count for a potential consultation bottleneck;
- inspect an informed-only pattern when the stakeholder has material impact;
- inspect unresolved or disputed cells before treating the matrix as an agreement.

Set thresholds for the scope and disclose them. A role appearing as A on three rows might be normal for a sponsor or a bottleneck for an operational approver. The matrix cannot tell which without authority, timing and effort evidence.

## Framework fit

Use standard RACI for recurring delivery relationships. Use:

- **RASCI** only when a distinct Support role changes how the work is coordinated;
- **DACI** for one consequential decision with a Driver, Approver, Contributors and Informed participants;
- **RAPID** when recommendation, agreement, performance, input and final decision rights all need separate treatment;
- a **decision-rights or delegation record** when formal authority is the real problem;
- a **capacity plan** when the question is whether the named people can do the work.

Do not switch acronyms merely to make an unresolved assignment appear complete. Record the gap and route it to the authority that can resolve it.

## Evidence and repair

For each finding, record the row/role, consequence, proposed repair, authority to confirm, source and due trigger. A repair changes the matrix only after evidence supports the new assignment. Preserve the prior version and confirmation history.

The renderer implements only transparent structural tests and declared count thresholds. Human review remains necessary for legal delegation, vendor obligations, segregation of duties, competence, workload and actual acceptance.
