Fictional additional intake message, 16 October 2026; the message is a teaching input, not a canonical decision record. Ada writes: "Can we add SCIM to the pilot? The customer is asking. Keep October 30 if possible." Mina requests analysis and a draft reply.

## Request breakdown

| Lens | Read | Evidence status |
|---|---|---|
| Classify | Addition to active project, with date preference | Stated ask |
| Sender | Sponsor Ada | Known role; this message does not approve a defined cost/scope impact |
| Literal ask | Add SCIM; retain October 30 if possible | Quoted message |
| Intended outcome | Meet a customer provisioning need | Inference; the customer's actual problem is unstated |
| Must-have | SCIM is requested | Not yet an accepted project requirement |
| Hard negative | None stated | Do not invent "no extra funding" |
| Success criteria | None stated for provisioning | Need use cases and acceptance owner |
| Constraint | October 30 preferred; B1 uses that date | "If possible" is not a feasibility result |
| Gap | Affected users, required provisioning behavior, estimates and funding impact | Unknown |
| Risk | Quietly adding excluded work could displace mandatory acceptance | Derived from B1 boundary |

The route is a change request, not a new approved project: SCIM is expressly excluded from B1. The next useful question is which customer outcome must be achieved for this pilot. That answer could support a smaller alternative; it does not justify silently replacing SCIM with another solution.
