# Delivery Approach Advisor: software example

Fictional training scenario. Values and thresholds are examples, not defaults for real projects.

## Dialogue at initiation

**Mina:** "Relay already runs Scrum. Should the SSO project simply follow the sprint board?"

**Advisor:** "Can the pilot tenant and security reviewers inspect usable increments during development, and which release decisions sit outside the team?"

**Mina:** "They can review increments. Ada funds the project; Lena accepts security evidence and Theo accepts service handover."

## Recommendation

Use iterative software delivery inside explicit project funding and release boundaries. Priya orders the product backlog; Developers forecast sprint work. Mina coordinates external dependencies and sponsor decisions rather than assigning Scrum commitments on the team's behalf. Reviews inspect the SSO increment and unresolved acceptance evidence.

The operating approach preserves a separate go/no-go decision for pilot release. A sprint finishing does not imply Lena has accepted recovery access or Theo has accepted support responsibility.

## Repair

**Flawed:** "Scrum removes the need for project governance."

**Corrected:** "Team delivery is adaptive; funding, cross-team dependencies, and release acceptance retain named decision authorities."
