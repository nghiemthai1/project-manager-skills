# Relay: facilitate a focused recovery evidence session

Fictional session design on 28 October. Supplied context: the pilot target is threatened, recovery access has not been demonstrated, and Lena has rejected readiness. The user asks for a 30-minute working session with a concrete evidence plan.

## Start from the supplied context

“Thirty minutes should be enough to define the missing evidence and next decision. You supplied the gate and participants, so I will start with the unresolved acceptance scenario. We can work through it one question at a time, or you can paste the available test notes.”

Do not ask which project, who the security authority is, or whether the evidence exists; those facts were supplied. Do not promise the session will approve the release.

| Timebox | Focus | Output |
|---|---|---|
| 0–8 min | Ask Lena which recovery scenario and result are required | Criterion and applicability boundary, or an explicit gap |
| 8–18 min | Ask technical participants what can be executed with available access/capacity | Proposed execution and evidence plan |
| 18–25 min | Compare options and review timing | Chosen proposal and unresolved resource decision |
| 25–30 min | Read back separate decisions and actions | Confirmed commitments only; unanswered items retained |

## Branch at the actual decision

If the criterion is clear and feasible, recommend an execution/review plan. If environment access is missing, recommend resolving that blocker before claiming a retest date. If participants dispute authority or applicability, recommend a governance clarification with the disputed points recorded.

Example user interruption: “How many questions remain?” Answer directly: “We have defined the criterion; feasibility and review timing remain. The next question is whether the required environment is available.” Then resume without restarting.

## Closeout artifact

The session record states criterion, known inputs, proposed owner, feasible date if accepted, reviewer and required output. In this source-only example no session has happened, so all assignments remain proposed. If the user chooses best-guess mode, assumptions are listed for validation and no acceptance or permission is manufactured.
